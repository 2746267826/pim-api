## 1. 建议怎样定义第一个可用版本

建议交付一个完整的安卓业务闭环，而不是将“可以本地录音”单独当作用户要求的成品：

> 课堂/会议开始时新建记录，离线录音、输入 Markdown、拍照和基础手写，右下角拖动调整手写块宽高；锁屏和切换应用时可靠记录并显示状态；结束后上传全部材料，逐段转写，再得到完整记录和独立分析。

这相当于总路线图 M1 与 M2 的安卓端纵向切片。M1 可以作为内部本地能力里程碑，但缺少云端整理和分析时，不能宣称完整愿景已经交付。也不必等待所有现有业务迁移成原生界面才交付笔记。

### 建议进入首个可用版本的范围

| 能力 | 最小可用边界 | 对应需求 |
| --- | --- | --- |
| 原生入口与本地笔记 | 集成现有安卓主应用和认证；新建、打开、编辑、可靠保存；Markdown 为主文档 | NOTE-01/02/05、NATIVE-01 |
| 记录材料 | 录音过程中写正文、拍照插入，离线保存，保留原始材料 | NOTE-04、REC-01、SYNC-01 |
| 基础手写卡片 | 嵌入正文、可再次编辑、保存原始笔迹；右下角拖拽直接调整宽高，不用滑块/预设档位；与首版一起交付 | INK-01/02/03/04 |
| 可靠录音 | 同篇多段、手动开始/停止；单段上限 3 小时、自动保存续段、暂停不计时，同篇累计不固定封顶；左下角紧凑悬浮条展示真实小波形、时长和状态；后台持续状态通知、本地回放；异常如实告知并尽量保住已保存内容 | REC-01/02/03/04/06/07、NOTE-05 |
| 完整提交 | 结束本次记录后统一提交；离线待上传、失败重试、材料完整性检查；不要求一个巨大请求上传全部文件 | REC-04、SYNC-01 |
| 正式转写 | 服务器 ASR，覆盖全部录音，每段单独可查；某段失败明确显示，不能冒充整篇完成 | AI-02/03 |
| 完整记录与独立分析 | 全部转写、手动正文、照片及对应版本的手写渲染图片共同参与；保留细节和主题结构，不只是短摘要 | AI-06/07/08 |
| 原文与结果分离 | 固定提交版本，处理后原笔记可继续编辑/补录；完整记录与分析可人工修订，重生成不覆盖用户稿；多端冲突保全双方材料 | AI-04、SYNC-02 |
| 安全边界 | 录音及云处理告知、用户隔离、凭据保护、敏感日志控制、删除及保留规则 | SAFE-01、AI-05 |

输入版本提示、明确重处理和冲突保全已作为六条规则获用户接受；具体控件、数据结构和版本保留策略仍需设计。账号、服务端处理配置与故障入口需要按实际流程交付，但不将“全套 AI 平台重建”作为首版前置条件。

### 不能替用户默默定掉的范围

| 能力 | 当前状态 | 建议如何处理 |
| --- | --- | --- |
| 其他平台手写输入适配 | 安卓基础手写首版已确认，含 OPPO Pad 4 Pro 首批实测；Windows 等后续输入与多端批次未定 | 不能将该安卓平板的基础记录/手写推迟至 M3；具体笔输入需实测，其他平台分别适配和验收 |
| Windows 记录与混合编辑 | 未来必须支持电脑记录；首批仅安卓记录可接受 | 后续批次单独验收，不能以电脑只读或查看转写代替录音记录能力 |
| Windows/Web 新笔记访问、编辑 | 已有多端目标，首版同步上线范围未确认 | 安卓闭环与跨端访问分开标状态，不把安卓先行写成永久删减 |
| 速览及 HTML/图片等导出 | 参考候选 | 先确认详细记录与分析体验；不因参考产品提供导出就自动塞进首版 |
| 任务建议写入任务模块 | 已明确的后续目标 | 保留 M4；用户确认后创建，不在草图里自动创建任务 |
| 实时转写 | 用户明确非必需、不紧急 | 后续可选，不是首版验收或近期本地模型选型的门槛 |

全量业务原生化继续走独立迁移台账，不能因完成笔记首版而被标记结束。

## 2. 页面流程与控制边界

| 页面/状态 | 主要内容与操作 | 需要避免的误解 |
| --- | --- | --- |
| 记录中 | 编辑区占主空间；不设常驻品牌栏，结束在右上角悬浮；拍照、手写入口；左下角紧凑录音悬浮条显示当前段状态、时长、小波形和暂停/继续 | 结束按钮与标题避让；波形不代表转写准确，也不单独证明文件已写入成功；不再常驻大录音面板 |
| 当前段暂停/停止 | 暂停或继续当前段；停止后可以录下一段，仍可编辑笔记 | 停止一段不等于结束本次记录；暂停不计时已确认，具体控件仍需设计 |
| 当前段满 3 小时 | 保存当前段，自动接续同篇下一段，段号变化但整次记录不结束 | 已确认行为；接续失败必须明确提示中断，不能只让计时或波形继续假装正常 |
| 后台通知 | 当前录音状态、段号、时长、返回记录入口 | 是持续状态通知，不要求悬浮窗；通知权限和锁屏设置影响可见性 |
| 整次结束确认 | 说明保存和提交哪些材料；可取消返回 | 结束整次记录与停止单段必须有可辨别的后果 |
| 离线待上传 | 本机材料清单、尚未云处理、等待/重试入口 | 本地完成、上传完成、AI 完成不是同一状态 |
| 处理中/部分失败 | 上传、逐段转写、整理/分析的进展；已完成的转写可先查看，失败段可重试 | 缺段时不显示完整成功；重试不要求重复提交全部已完成材料 |
| 处理结果 | 原笔记、各段录音文字、完整记录、独立分析四个内容入口 | 区分原始记录、ASR 文字和生成产物，而不是四份重复摘要 |
| 来源变化 | 修改原笔记后提示旧结果基于旧版；明确发起再次处理 | 不静默以旧分析冒充最新结果，也不让重处理覆盖用户编辑 |

用户已确定录音采用应用内左下角紧凑悬浮条，取消早期“大底部卡片/顶部段落卡片”的位置对比。当前草图落实为：

- 常驻条只保留小波形、时长、当前段状态及暂停/继续；停止某段、录下一段等操作通过紧凑展开层访问，不一直占用正文空间。具体展开控件属于建议。
- 插入入口放在右下侧，展开拍照和手写入口；不是让用户到别处录入后再手工搬回笔记。
- 悬浮条属于当前应用页面，不是覆盖其他应用的系统悬浮窗，不需要因此申请悬浮窗权限；退后台仍走系统持续通知。
- 原生界面要给正文末尾、光标和手写拖拽柄留出操作空间；键盘弹出时以可编辑区域为边界避让，不能挡住正在输入的内容。
- 页首取消“PIM 笔记”常驻品牌行，保留本篇标题和保存状态；整次结束操作在应用内右上角悬浮，沿用结束确认。原生时需适配系统安全区、标题和滚动后的可达性，不靠盖住正文节省空间。

草图没有模拟真实安卓键盘、系统返回行为、权限对话框或文件写入。左下角位置不等于已经解决原生界面的键盘遮挡、系统安全区和滚动问题。

### 录音段、笔记累计与内部分片

- 用户可见的一段录音上限为 3 小时；这不是 Android 或所有 ASR 服务共同规定的技术上限。
- 一篇笔记可包含多段，全部录音累计不另设固定业务时长上限，因此可超过 3 小时；所有段仍参加整篇处理。实际存储、电量、上传及服务额度有限，配额应透明，不能静默截断。
- 内部可为可靠保存、断点上传或 ASR 限制进一步分片，但用户仍按原来的录音段回放和查看文字；不能把处理分片混成新段，也不能等录满 3 小时才保存本地文件。
- 用户已接受：录满 3 小时保存当前段并自动接续下一段，仍在同篇笔记中，整次记录由用户手动结束；若提供暂停功能，只累计实际采集时长，暂停期间不触发续段。接续间隙及异常需真机验证，不承诺零丢帧。

## 3. Markdown 与手写不能只靠外观确认

正文形态已经明确：普通自上而下的 Markdown 文档，嵌入可再次编辑的手写卡片，不是无限画布。基础手写是首个安卓版本的必交能力，不能继续记为 M3 才开始的可选项。

尺寸交互已确定：抓住卡片右下角直接拖动，宽高随手势变化，不用滑块或固定尺寸档位。宽度应服从正文可用区域，避免把普通文档变成横向无限画布；具体最小尺寸和跨端映射仍属实现细节。放大只增加空白，不把笔迹随卡片拉伸变形；真实画布、缩小与笔迹边界的处理仍需组件验证。

当前草图用文本输入区与附加材料示意布局，能试拖拽改宽高，但不等于已经验证：

- 在任意正文位置插入图片或手写卡片、光标定位和段落顺序。
- 原生触控/手写笔拖拽、正文滚动/书写/调整尺寸之间的手势冲突，以及笔迹边界处理。
- 真实笔输入、擦除、撤销、选区、手势冲突及不同设备输入。
- Markdown 与扩展块往返、跨端编辑和导出兼容。

这些需要在实际编辑器和目标设备中验证。可编辑笔迹是原材料，供 AI 使用的图片只是派生输入，不能只存截图后宣布手写编辑已完成。M0 先证明正文模型能保留块的位置、尺寸、身份和可迁移笔迹，M1 交付基础编辑与尺寸拖拽，M2 将对应版本的笔迹图纳入整篇分析。

### 已确认的正文实施方向

- 原生宿主及录音、存储、通知和后台任务保留，正文使用 PIM 自己构建并随客户端离线发布的 Tiptap/ProseMirror 开源编辑模块；不再以“所有正文交互必须自己原生实现”为目标，也不退回远程 WebUI 壳。
- 沿用现有 Web 的 React/Tiptap 基础研究可复用部分；不照搬 OPPO 混淆 H5 或私有桥接，不强制改用 Vue。准确上游版本、扩展组合及手写嵌入方式由真实混合文档验证确定，不在本轮编造版本或云端数据结构。
- 编辑器只是文档交互层。原生层负责可靠持久化、材料权限和固定提交版本；正文必须收到持久化确认才显示已保存，渲染重建不应中断录音。桥接、认证和不可信内容边界按总路线图的职责决议执行。
- 保留普通 Markdown 内容与可迁移的版本化混合原稿。手写仍保存向量和块身份/尺寸，AI 使用对应版本的派生图；任何引擎适配都不能静默删除未知扩展或用图片替代可编辑笔迹。

架构方向已定，下面的验证是为了确认实现可交付，不是再次让用户在“完全原生正文”和“离线编辑核心”之间选择。恢复开发时给验证设定明确范围，复用真实录音及材料层，不再交付一个不能接回主应用的纯文本 demo。

| 验证范围 | 必须证明的行为 | 当前证据边界 |
| --- | --- | --- |
| 中文输入与编辑 | 真实中文输入法组合输入、选区、粘贴、换行、列表和撤销/重做不丢字；工具栏、键盘与光标可达 | 新核心新增独立测试和设备侧验证；具体执行结果见本轮 PR。模拟器 InputConnection 不能替代 OPPO 实际输入法/手写笔验收 |
| 混合长文 | 长正文、多照片、多张可编辑手写能在光标处插入、保存、重开；手机/平板、大字号和横竖屏不遮挡正文 | 须在真实应用验证，不只展示静态排版 |
| 手写与尺寸 | 保留向量再编辑、右下角自由拖宽高、放大不变形；书写/掌触/滚动/拖拽可区分 | OPPO 实际笔和掌触仍未验收；参考包没有证明其手写模型可直接复用 |
| 原生生命周期 | 断网记录、切应用/拍照、编辑视图或渲染进程重建，已确认保存的正文/附件可恢复且录音独立继续；未保存状态如实提示 | 须区分渲染故障与整应用被强制停止，不承诺系统杀进程后仍持续录音 |
| 旧笔记迁移 | 用当前预览原稿及固定材料版本作夹具，核对正文、块顺序/尺寸、向量、照片及全部录音关联；迁移失败不损坏旧数据 | 新格式写入前验证可重复迁移、失败保全及旧客户端只读/不支持行为；不要求用户卸载或清数据 |
| Markdown 与兼容 | 普通内容往返不丢信息；扩展内容及附件可迁移；未知版本/节点保留原数据并明确只读或不支持，不保存破坏性降级稿 | 纯 Markdown 不假装能单独承载向量/音频；具体导出范围不因此扩大 |
| 桥接与主题 | 只访问本篇获准材料，外链/任意页面不能获得桥接权限，凭据不进入脚本；正文与原生引用同一语义主题 | 本轮实现精确离线资源/主框架来源、session/epoch/sequence 校验和宿主题映射；不开放任意材料 URL，执行证据见 PR。字体/动画可用不等于桥接代码或播放器已获授权 |
| 后续跨端 | 复用同一文档兼容夹具，分别验证 Windows/Web 的编辑、未知块和材料访问 | 属对应平台批次，不以 Android 或引擎相同宣布跨端完成 |

### 现有本地预览分支实现（不是长期编辑核定稿或云端契约）

- PR #36/#39 的原生 `EditText` + Markwon 4.6.2 路径继续作为显式源码编辑/不支持格式的回退。[PR #40](https://github.com/2746267826/pim-android/pull/40) 默认由离线 Tiptap 3.31.3 / ProseMirror 编辑每个 Markdown 叶块，提供原生视口格式栏，不随长叶块顶部滚走；打开/预览/改主题不规范化原文，用户实际编辑才序列化。HTML、Markdown 图片/引用定义/扩展脚注、front matter 或超过 50 万字符的块先保原稿走源码；不支持粘贴明确拒绝并提示改用源码，不无声丢字段。可编辑 JSON 清单、未知字段、照片和向量原稿保持 schema-v1。
- **本轮临时简化必须补齐**：成熟核仅管理文本叶块，照片/手写继续作为原生块穿插；撤销是活跃叶块内的，不跨插入材料、源码切换和视图重建。超长叶块外部高度封顶后内部滚动，大量块/整篇性能尚未验收。`44f1cd3` 统一原生光标滚动；当前完整手机回归 26/27，剩余首次结束确认失败，窄屏/平板整组因此未完成，不能把提交前针对性通过替代完整验收。渲染故障显式核对继续、真实终止和离屏提交回归仍待补，集中跟踪于 [Android #41](https://github.com/2746267826/pim-android/issues/41)。OPPO 输入、真笔/掌触和长时录音继续是缺口。参考字体/动画本轮未采用，仍为已确认可用、待按页面选用。
- 富文本插入位置用“期望原文 + 光标两侧各自合法 Markdown”表达，不把 ProseMirror offset 当源码字符下标；取消相机/相册不提前改写原稿。大锚点原子保存为私有文件、Activity 只存 token，重建仍能定位；原文变化时拒绝旧锚点，不偷偷插在末尾。离开/结束/插入/导出/模式切换先等待输入法提交；失败不假装成功。渲染器崩溃前从未交给原生层的字不能承诺恢复，必须提示核对最近保留原文。
- 正文只加载 APK 内三个明确资源，网络/导航/file/content/iframe 禁止；使用受限 `WebMessageListener`，不开放全局 `addJavascriptInterface`。主框架来源、协议、随机会话、native epoch/本地序号校验隔离旧消息；读取同步原生仓库避免 Compose 旧回显覆盖快速输入。账号凭据不进脚本，颜色/字号/间距由宿主题传入，字号缩放只算一次。

本轮[服务器收包实现](../architecture/native-notes-material-upload.md) 是 M2 前置：原稿/全部录音的完整清单、分块续传、摘要与格式核对、版本比较及冲突保全已实现。它只发布“材料已上传/发生冲突”，不产生处理中的假状态。Android 仍需账号/服务器绑定、明确上传同意、后台队列和恢复；模型同意、ASR、双产物及修订保护继续是完整 MVP 必需项。
- 插入以选中文本块中的光标为锚点，保留前后文字。手写用文档坐标向量保存，右下角拖拽增加空白或收缩至笔迹边界，不把笔迹分别按宽高拉伸；窄屏统一缩放整个卡片，不改写原始点。实际 OPPO 手写笔、掌触和滚动表现仍需实测。
- 照片保留私有原图；相机只获得专用临时目录的 URI，不开放笔记/录音目录。取消或校验失败不插入假图片。PNG 手写图是按内容标识的派生材料，不能替代向量原稿。
- 本批“导出文档包”只包含正文、照片、向量及派生图，以包内相对路径引用；明确不含录音，不是完整记录备份或上传包。未知材料类型或附件缺失阻止完整导出，不自称已实现跨端往返编辑。
- 本地结束与云提交分开：混合文档片只结束录音并保存本机，不显示假的待上传/已转写/分析完成。录音会话持久记录所属条目，页面重建或打开另一篇不会改绑；后续本机材料版本片见下节，不将其冒充服务端版本保护或六条规则全部交付。

### 本机完整材料版本（提交前置，不是服务端契约）

- 结束先等待本篇录音停止、原稿可靠保存，再持久化固定请求：原稿 JSON、全部录音会话及用户段/内部分片清单。后台准备只读这些固定输入，不从当前新稿重新拼材料；未变输入重复结束复用原请求。无法确认归属的损坏录音清单会阻止完整准备，不能静默漏音频。
- 本机准备覆盖普通 Markdown、照片原字节、向量笔迹及该版 PNG、全部录音元数据与 WAV；只有所有材料核验成功才提交完整清单。失败/中断保留请求及已固定材料，重试从原版本继续，仍可编辑和同篇补录。已中断但可读取的录音保留中断标记，材料齐备不等于录音全程连续。
- 首次唯一材料会复制到应用私有内容寻址存储，以隔离后来的原文件变化；以后版本复用相同字节。摘要、拷贝和 ZIP 导出分片流式处理，不把长音频作为一个内存小附件；不是物理零额外存储，也未完成 GC、配额或删除策略。空间不足明确失败。
- 旧的“文档包（不含录音）”继续保留；“固定材料包（含全部录音）”从指定版本导出，包含可编辑原稿、录音清单和每文件相对路径/大小/摘要。导出前再次校验固定副本，缺失/损坏不报完整，目标写入失败可能留下不完整 ZIP。尚无包导入或服务端收包功能。
- UI 明示本机准备中/失败/齐备和**未上传**，不自动上传至当前登录账号，也不声称服务器已排队处理。下一片仍须先在 `pim-api` 实现长附件、身份/服务器绑定、同意/配额与完整性核验并导出唯一契约，之后 Android 接入；ASR、多模态分析和跨端冲突继续保留。

## 4. 生成结果的建议结构

- 完整记录按内容主题整理，保留重要细节、数字、条件、争议和明确结论；有真实比较才用表格，不强行套科研模板。
- 独立分析提炼整体主线、未解决问题、边界和行动建议，区分原材料陈述与 AI 新归纳。
- 引用、数值和来源不能伪造；没有负责人、截止日期或优先级时，不补造成已经确认的决定。
- 逐段正式转写可以独立查看；整篇处理覆盖全部材料，不只用当前选中段或最后一段。
- 草图中的“来源”只演示回到录音段，精确时间戳、逐字稿校订、说话人识别和点击定位播放尚未确认为首版能力。
- 速览是候选浓缩阅读层，不替代原文和详细结果；若实施，应关联同一输入版本，避免另编一套互相矛盾的数字。

用户参考材料的可借鉴点及证据边界见总路线图“分析结果与速览图参考”一节。原始研究截图、HTML 导出和私人内容不纳入产品仓库。

## 5. 状态模型要在实现前独立设计

草图为切换画面使用的场景名不是后端状态机，也不是 API 枚举设计。实现至少要区分：

| 状态维度 | 需要表达的事实 |
| --- | --- |
| 音频段 | 采集中、暂停、停止、异常中断，以及哪些音频已可靠保存 |
| 本次记录 | 是否仍在记录、是否结束、是否允许补充材料 |
| 材料版本与提交 | 哪个版本的哪些材料已准备、已上传并验证，是否存在新的未提交修改 |
| 正式转写 | 每段等待、处理、完成或失败，不以全局一句“处理中”掩盖缺段 |
| 生成产物 | 完整记录与分析各自的处理结果、来源版本和失败情况 |
| 跨端编辑 | 保存基于哪个服务端版本；冲突时如何保留双方内容 |

用户本轮明确接受上一轮六条规则：本地保存后后台提交、处理期间继续编辑、结束后同篇补录、完整记录/分析可人工修订且重生成不覆盖、失败按步骤重试、多端冲突保留双方完整材料。以下展开这些产品规则，关联 REC-04、AI-04、SYNC-01/02；具体界面和技术实现仍待设计，不代表服务端已有幂等、输入快照或结果版本支持。

### 5.1 结束一次记录：保存与云处理分开

用户流程为：结束并整理 -> 完成本地保存 -> 固定本次输入版本 -> 上传并核验材料 -> 各段 ASR -> 用全部材料生成完整记录和独立分析。这里是已确认产品行为的展开，不是 API 枚举或数据库表设计；控件文字仍可细化。

- 停止并完成当前段的保存后，再建立待处理材料清单；包括 Markdown、照片、手写块身份/顺序/尺寸、可编辑笔迹及对应渲染图、所有录音段。保存或渲染失败应明确阻塞完整提交，不把半份材料称为已提交。
- 即使无网络，也先保存为待上传，可离开页面；恢复网络后按上传设置重试。仅 Wi-Fi、移动网络告知和后台上传限制仍需设计，不默认承诺任何网络环境都会立即完成。
- 提交固定的是内容及其不可变引用，不要求每次物理复制所有大音频。文件可独立续传/重试，服务端校验本版本材料齐备、归属和完整性后再开始正式处理。
- 重复点击和网络重试应关联同一次提交，不创建重复笔记或重复付费任务。页面分别显示本地保存、上传、转写和两类产物状态；只展示可证实的进度，不虚构剩余时间。

### 5.2 提交后编辑与补录：旧任务不追着新稿变化

| 操作/场景 | 产品行为 | 需要保护的边界 |
| --- | --- | --- |
| 已提交 A，上传/处理期间又修改正文、照片或笔迹 | 保存同篇的新材料版本 B；A 继续处理，界面标明尚有未纳入结果的修改 | A 的正文、附件及手写渲染图不能被 B 偷换，编辑器无需一直锁住 |
| 等待上传时继续修改 | 原已提交的 A 保持不变；新修改属于待下次提交内容 | 不因断网重试就把任务输入悄悄换掉 |
| 结束后继续补录 | 允许在同篇增加新录音段，旧段不覆盖；更新输入版本 | 不强迫新建另一篇笔记，也不宣称旧分析已经包含补录 |
| 希望更新完整记录/分析 | 明确点击更新，提交当前版本全部材料；不因每次自动保存就自动调用 AI | 更新前说明范围，旧结果保留，不用旧版结果冒充最新 |
| 只改笔记，音频没有变化 | 可复用仍有效的逐段转写，再按新版本完整材料整理/分析 | ASR 配置或来源修订变化时要核对复用有效性；不能只分析新增段 |
| A 和 B 两次处理完成顺序颠倒 | 每份结果关联自己的输入版本，旧任务晚返回不顶掉新版结果 | 任务完成时间不等于输入版本的新旧 |
| 某段转写失败，或只有一类生成产物完成 | 保留可用结果，具体指出缺哪段/哪类产物，重试对应失败步骤 | 未齐备时不标全篇完成；基于 A 的重试仍使用 A，不混入尚未提交的 B |

例子：下课提交 A 后补写了一条结论并补录五分钟，成为 B。A 的结果仍可读，但显示未包含这些补充；用户更新后，B 使用全部录音及最新正文/照片/手写生成新结果，不只是总结新增五分钟。

### 5.3 完整记录与分析：允许人工修订，不让重生成覆盖

- 原始笔记一直由用户编辑，AI 不改写它；逐段 ASR、完整记录和分析仍是分开的内容层。
- 完整记录和分析可以手动修改；保留生成原稿、人工修订稿和下一轮生成结果的区别。新结果出现时不自动覆盖修订稿，可比较或明确选用；这一产品规则已确认，比较及选用的具体界面仍需设计。
- 只修改生成结果不自动反写原笔记或假称已经更正原始录音/转写。若未来支持转写校订，需独立定义原转写、校订与后续分析的关系，不在本轮偷偷加入首版。
- 保留旧版本不等于承诺永久保留全部音频与所有历史；配额、归档、删除及处理中材料的保留边界另行确定，禁止无告知清理当前仍需使用的材料。

### 5.4 多端冲突：先保全材料，再谈合并

采用版本校验和双方材料保全，首版不默认实时协同或自动合并；不以长时间锁住编辑器代替冲突保护。记录阶段本地优先减少了并发场景，但不会自动消除手机/平板/电脑事后编辑的冲突。

- 本地没有未保存/未同步修改时，可更新到服务端新版本；本地有更改时，保存必须校验它所基于的服务端版本，不能只比较客户端时间或按最后上传者覆盖。
- 版本不匹配则保留服务端版本和本地完整冲突草稿，明确提示；不能先下载远端覆盖本地，再让用户设法恢复。
- 草稿保护范围包括正文、手写原始笔迹、块身份/顺序/尺寸、照片和录音关联，不是把文本复制出来就算保全。材料引用还需可读取，不能生成指向已清理文件的空副本。
- 默认不自动拼接 Markdown、合并两版笔迹或让 AI 选择真稿；先支持保留两份、查看差异并由用户明确解决。冲突副本命名、具体界面和服务端存储方式仍待设计。

## 6. 首版必须用真实证据验收

浏览器草图最多提供布局与交互证据，不能证明下面这些能力：

| 场景 | 实际验收关注点 |
| --- | --- |
| 断网完整记录 | 正文、照片和多段录音本地可用；结束后准确显示待上传 |
| 正常锁屏、切换应用、前后台反复切换 | 采集与保存不中断，返回后状态一致，通知不依赖页面存活 |
| 录音中拍照 | 目标设备相机/权限流程与录音共存，照片与正确记录关联 |
| 来电、其他应用占用麦克风、权限变化 | 中断/静音等真实状态可见；不继续用正常波形掩盖异常；尽量保全已写入材料 |
| 空间不足、进程异常、强制停止、重启 | 不承诺无条件连续录音；明确已中断，并验证已保存材料的可恢复性 |
| 约 100 分钟典型课堂 | 两台目标安卓设备上的文件可回放、时长合理、无静默截断；锁屏/切应用/拍照组合下验证温度、电量和本地空间 |
| 180 分钟单段边界与多段累计超过 180 分钟 | 验证已确认的到点自动保存续段、暂停不计时；实测段边界间隙、材料完整性与回放，清楚展示接续或失败，不假称零丢帧；累计超过单段上限仍可保存并完整提交 |
| 上传/ASR/分析分别失败和重试 | 不删除原始材料、不假报完成、不重复创建记录；缺段被标识，重新处理的输入版本明确 |
| 完整云端处理 | 全部录音逐段可查，手动正文和照片确实参与；图片输入、长内容覆盖与原文不被覆盖有证据 |
| 首版基础手写 | 真正能书写、再次编辑、右下角拖动宽高，保存重开不丢笔迹或块布局；AI 实际收到对应版本的渲染图片，而不是只有本地文件路径 |

### 已接受的视觉与功能衔接方法

用户已同意先建立覆盖整个 PIM 的视觉语法，用笔记关键页面验证，再立即接入真实功能；不先设计所有页面，不等通用组件库齐备才录音，也不先裸做完整功能再统一换皮。现已确认蓝色基调与紧凑页首，并要求统一主题和基础组件引用；以下产出边界用于执行，不将局部确认误写为所有字体、布局或原生实现已经完成。

| 起步产出 | 做到什么程度即可进入真实切片 | 暂不做什么 |
| --- | --- | --- |
| 全局视觉基础 | 延续现有产品语言，明确内容优先、语义色、中文字体层级/行距、间距、边界、必要主题和状态表达；用实际长文验证可读性 | 不在所有页面堆装饰，不预先承诺完整主题/皮肤系统 |
| 关键页面样板 | 记录编辑页与结果阅读页，包含手机/平板布局及录音、离线、失败、来源过期、人工修订等关键状态 | 不用纯静态正常态截图代替键盘、笔输入及异常体验验证 |
| 必要组件 | 复用平台按钮/输入/对话框；按需要提炼紧凑录音条、手写块框架、材料插入、处理状态和版本提示，并在真实页面使用 | 不重写所有平台控件，不为未出现的通用需求先建大型组件库 |
| 原生验证 | 将上述主题和组件应用于首个安卓本地记录切片，验证触控/键盘/手写、字号缩放、可用空间和前后台状态 | 不要求 Windows/Web 同时实现同一批组件，不把浏览器模拟当成原生验收 |

共享的是产品识别、视觉语义和规则，不是强迫 Compose、WPF 与 Web 共用 UI 代码或同一像素布局。新共性从实际页面提炼；录音、存储、恢复与混合编辑模型不依赖视觉层，后续调样式不应重做数据链路。

颜色、字体层级、常用间距/圆角等由统一主题资源维护，页面引用语义；按钮、输入、状态提示等共享基础组件和必要变体，不允许各页复制样式或散写色号。具体平台资源方式见 [PIM视觉基础与笔记样板](native-notes-visual-foundation.md) 第 3.1 节，样板资源化不代表客户端已有改造已交付。

Android 已有 `PimTheme`（主入口使用）和 `PimSection`，Windows 已有主题资源字典。首批安卓改动在这些基础上演进，不新增互不相认的主题；跨端是否一致、完整主题及无障碍支持仍需分别验证，不能因主题文件存在就标为完成。首批基线见总路线图，后续切片继续从最新 `origin/master` 复核。

本轮规范见 [PIM视觉基础与笔记样板](native-notes-visual-foundation.md)：当前记录页方向为“清晰文档”，“安静纸面”保留阅读布局参考，已确定的蓝色与操作位置共同生效。独立样板覆盖手机/平板、原稿及结果阅读、字号/留白和十类状态；均无真实麦克风、相机或云端调用。右下角尺寸拖拽可以操作，但示意笔迹不是已选型的手写编辑器。原生薄主题与组件复用已合并，真实录音/混合笔记、PR #39 预览及 #40 离线核分别有独立证据，不能混用。字体/动画的可用确认和资源化规则见视觉规范第 3.2 节，不再扩展大量静态页面。
