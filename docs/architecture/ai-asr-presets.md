# ASR 接入预设与单音频调用

更新日期：2026-10-27。本切片实现“选择预设 → 独立ASR配置 → 单音频调用 → 转写/记录/原音频核对”。当前仅注册 MiMo，准确 head 验证和合并以本切片 PR 为准。**这不是整堂课的上传/分段调度或完整笔记MVP**，全部目标继续引用[唯一总路线图](../product/native-notes-roadmap.md)。

## 预设与扩展入口

`IAiAsrPreset` 是受信任代码的厂商策略接口；`AiAsrPresetRegistry` 通过依赖注入收集策略、按ID查找并输出页面使用的目录。预设集中声明版本、默认地址/模型、操作路径、允许模型、音频格式、语言、当前输入限制，以及调用和实际请求审计方法。当前目录只有 `mimo-asr` v1；没有按厂商名字散落在控制器/页面中的分支，也没有用户可执行的任意HTTP/脚本模板。

新增厂商的步骤：

1. 新建一个实现 `IAiAsrPreset` 的适配器，复用该协议的成熟 SDK，并把厂商默认值/限制/参数放在该实现中。控制器不猜测“所有ASR都是同一接口”。
2. 实现请求审计，确认实际模型、输入材料和参数，保存可核对的音频引用。适配器必须使用有界、无隐式重试/跳转的受审计传输，不能跳过应用的账号/目的地同意。
3. 注册一个 `IAiAsrPreset` 服务；目录与通用页面自动出现新预设。为新增协议、参数/错误和真实小样补测试；目录不得重复ID。调用/审计行为变化需更新预设版本，旧确认不可套用新版本。

同协议的新模型/默认值在适配器集中维护；新认证方式或协议需要相应成熟SDK适配，不能只换一段JSON就冒称兼容。当前共享单片文件入口仍有限制，新增超出该入口的格式/大文件能力时须同时完善校验/存储，而非只放大目录字段。

## MiMo 当前实现

MiMo 通过 OpenAI-compatible Chat Completions 的单条 `user/input_audio` 识别音频，不把音频路径或文字冒充声音。当前只允许 `mimo-v2.5-asr`。默认API根地址与模型来自预设，用户可以配置自己的兼容代理/地址；保存时支持API根地址或该操作的完整地址，路径规范化由适配器负责。实际请求仍绑定到本次展示的操作地址。

复用已有 Microsoft.Extensions.AI / 官方 OpenAI .NET SDK，使用 `DataContent` 生成原生音频内容，支持 WAV/MP3 和 auto/zh/en。厂商的 `asr_options.language` 通过官方SDK选项扩展设置，没有自写请求协议或流式解析器；不发送文本模型的通用输出token参数。SDK的 `ChatCompletionOptions.Patch` 目前带实验性诊断，仅在 MiMo 适配器这一处显式采用；未关闭全局编译诊断/CI，固定当前SDK组合并用实际请求测试约束，升级SDK需回归这里。

模型配置新增可空 `asrPresetId`。旧ASR能力声明保留且不自动绑定MiMo；未选择预设不能执行转写。新ASR配置必须选择预设并使用独立的语音转写能力/凭据，不能混入文本或视觉；已保存ASR配置不转作文本/视觉，切换厂商预设要重新填写凭据。普通旧客户端编辑时省略该字段会保留已有预设，移除/变更默认模型仍按原revision规则处理。

## 用户流程、记录与恢复

管理员“设置 → AI设置 → 添加ASR配置”选择预设，默认地址和模型自动填入，填写凭据后保存。设置默认语音转写模型、启用SDK直连，在“音频转写”选择音频/语言，核对预设版本、模型和实际地址后明确发送。音频、语言、目标配置或预设版本变化后重新确认；服务端逐项校验，客户端地址只用于比较而不覆盖路由。

- 单次意图/音频清单先持久化，原音频通过既有文件系统默认来源保存成功后才发模型。无云盘用内置来源；来源失效明确失败，避免静默换账号/云盘。
- 实际SDK音频内容审计为 `pim-ai-audio:<id>` 引用，原字节/格式/大小/SHA256可核对；实际转写、完整响应、模型/预设版本、语言、结束原因、Token、服务商报告音频秒数都保留。报告时长与费用未知时不推算或当零。
- 正常stop且转写字段为字符串可成功，空字符串按原样保存并提示试听核对，不擅自补字；缺字段/截断/过滤不算完整成功。空结果不证明录音一定静音，真实识别质量须另验收。
- 原音频清单/内容仅发起账号可读，其他管理员也不能读；临时Blob URL关闭即释放。读取重新核对摘要，改图同理的改音频/删除/来源失效不会用另一份文件冒充原输入，原转写记录保留。
- 同用户/请求ID幂等，变更输入返回409；取消后只核对，不自动重发。SDK无通用重试/重定向。总并发4、ASR最多2，时限包含材料保存。运行意图的外发状态为未知，崩溃/写库失败/超时不推断上游未执行，也不保证撤销费用或恢复未持久化回复。

## 当前限制与MVP缺口

本次单音频入口 WAV/MP3、最多4MiB，做Base64/大小/签名识别而非完整编解码/内容扫描；该上限来自目前单片附件存储能力，是PIM限制，不是宣称MiMo的统一上限。它不承载100/180分钟整条录音，更不削减同篇多段录音目标。后续须按固定原材料版本、厂商实际限制及既有后台设施实现全部分片/时偏/覆盖、持久步骤、失败段恢复与逐段结果。

当前非流式；流式/中断部分转写、普通客户端/Android上传、后台长材料任务、完整记录和独立分析/人工修订保护均未交付。音频保留期/回收、上传未知窗口对账与大文件存储还需补齐，不自动删除用户文件掩盖不确定状态。全部项目继续记在MVP差距表。

## 验证分类

厂商参数/请求使用官方SDK的真实序列化测试；目录扩展用仅测试注册的第二策略证明，产品目录仍只有MiMo。隔离本机HTTP/默认内置文件测试覆盖单音频、语言、所有者、请求幂等和改动摘要冲突；旧文字/视觉、笔记材料和EF快照独立回归。

经用户明确授权，仅向指定MiMo ASR模型发送离线生成的公开短句；自动/中文/英语三组选项均正确转写并保留实际用量和原音频引用，密钥隐藏输入、只在内存。真实服务层、合成网页API、真实本机文件HTTP与设备/长课堂质量分别记账，不能互相替代。最终完整数据库/API/Web/镜像和准确head CI以PR为准。
