# 多图视觉调用与原始图片留存

更新日期：2026-10-27。本切片接通管理员“图片与正文 → SDK → 回复/记录 → 原图核对”，复用已有模型设置、请求幂等、状态和统计。当前实现/合并以本切片 PR 的准确 head 为准；完整笔记 MVP、正式 ASR、原生客户端和课堂质量尚未完成，范围继续引用[唯一总路线图](../product/native-notes-roadmap.md)。

## 实际使用

在“设置 → AI 设置”选择已声明视觉能力的模型及默认值，启用 SDK 直连，切换到“图片与正文”。选择 1～4 张 PNG/JPEG、填写正文/系统提示，核对图片顺序、模型名称和目标 API 地址后确认发送。更换图片、模型、地址或配置 revision 后旧确认失效；服务端也逐项核对，客户端传来的地址只用来比较，不能覆盖实际路由。

回复可在当前卡片查看，完整记录包含实际消息/上下文、回复、模型快照、结束原因、用量以及图片材料。图片不在数据库中重复保存多份 Base64：SDK 实际正文中的图片内容转换为 `pim-ai-image:<id>` 审计引用，另存的原始字节、顺序、MIME、大小和 SHA256 可还原该输入。文本内容按原值保留，不用摘要替代；该表示不是原封不动的二进制 HTTP 报文。

原始图片仅调用发起账号可列出/读取。既有管理员全局文字日志权限不自动授予图片读取权限；其他管理员查看文字记录时会看到权限提示。图片接口无外部直链，不把云盘凭据、预授权地址或认证头作为模型输入。

## 文件和故障边界

- 通过现有 `IFileAttachmentStore` 存入发起账号默认文件来源的 `/PIM/ai-calls/<logId>/`；未配置云盘时使用已合并的内置来源。已选择来源失效时明确失败，不静默换云盘/账号；本批没有另外搭建文件系统。
- 请求意图和图片清单先持久化；全部原图和定位引用保存成功后才发模型。中途失败保留已知的部分引用，明确本次未发送完整图片集；同请求 ID 核对/重放不会自动补传或再次调用。重新处理要明确新建请求，跨账号重放被拒绝。
- 官方 SDK 负责图文请求生成与解析。审计处理器在传输前检查图片数量、顺序与实际字节是否匹配；SDK 丢图或替换图即拒绝整个调用。文本与视觉共用每进程 4 并发，视觉最多 2；SDK 不自动重试、不跟随重定向、不切换供应商。
- 同一时限包括图片保存及模型等待。取消/超时、错误、截断、未知状态与结果写库失败沿用[文字切片边界](ai-text-model-settings.md#幂等故障与实际限制)，不保证撤销上游执行或费用，不保证恢复从未持久化的回复。
- 尚未写入最终结果的运行意图将 `providerAttempted` 留为未知；进程在外部请求后退出时，不能用旧元数据断言“没有发送”。只有可确认的受阻/终态才记录相应布尔值，重开仍不自动重发。
- 每次读取图片重新检查大小与摘要。用户在“文件”中修改/删除图片、解绑来源或来源不可用时，不展示另一份文件冒充原输入；文字记录和指纹仍保留，界面可重试读取。文件源可编辑，因此**不承诺用户删除/改动文件后仍可永远恢复图片**。
- 暂无 AI 图片独立的保留期/回收任务。上传成功但定位响应丢失、写库持续失败等窗口可能留下文件，需要后续清理/对账；不自动删除用户文件来掩盖不确定状态。

## 限制与后续

| 项目 | 当前边界 |
| --- | --- |
| 图片 | 1～4 张；单张不超过 4 MiB，合计不超过 8 MiB。验证 Base64、字节大小与 PNG/JPEG 文件签名，不引入图片编解码框架，不宣称做了深度解码/内容安全扫描；损坏或供应商不支持时保留失败结果 |
| 类型和质量 | 本批 PNG/JPEG；WebP/HEIC 等格式准备、照片压缩/方向处理、公式/笔迹等真实材料质量仍待补。不静默转码、裁剪或丢弃任何一张来满足限制 |
| 调用 | 非流式 OpenAI-compatible Chat Completions；既有 4 MiB 完整响应上限和实际 Token/未知费用策略不变。大图片、长材料和流式/中断部分回复不是已完成能力 |
| 业务 | 这是通用管理员视觉入口，尚未接 Android 上传、固定笔记材料版本、全部照片/对应手写图处理、完整记录/独立分析及人工修订保护；不能用此替代 M1+M2 验收 |

需要给普通客户端和后台笔记任务接入时，继续使用业务授权、固定材料/处理版本和已保存的目的地同意，不向普通用户开放管理员控制台，也不让模型选择权限、真稿或执行写操作。

## 实际验证分类

- 后端测试使用官方 SDK、合成红/蓝 PNG、隔离数据库/文件目录及真实本机 Kestrel HTTP，核对完整文本、两张不同图片、默认内置文件来源、请求幂等、缺图拒绝、目标变化/未确认拒绝、取消、所有者隔离和改图摘要冲突。EF 迁移只新增 `ai_call_images`，旧材料签名判断共用 helper 后做回归。
- 已按用户明确授权对其本机网关的指定模型进行 4 次真实服务层调用：简单文本正确，两图与交换顺序的颜色均正确，1 Token 上限返回 `length` 并记为 `Incomplete`；实际用量可见、费用未提供。输入均为合成公开材料，密钥只在进程内存中，文件接口/网页验证另列，不冒称真实笔迹、课堂或 OPPO 验收。
- 网页单测覆盖目标确认/变更失效、实际正文与图片载荷、取消后只查询、超限和原图权限/临时 URL 释放。`qa-ai-vision.mjs` 用真实构建页面及合成 API 验证桌面/手机，核对图片确实解码并可滚动到弹窗按钮上方、配置更新撤销确认、进行中切页、权限、改图提示和统计；不是实际云盘/模型联合验收。
- 契约从真实 Test Swagger 导出：新增视觉提交/核对及图片清单/内容 4 条路径，原 300 条保持不变，生成 Web 类型；临时导出测试不入库。最终完整回归、构建和当前 head CI 以 PR 为准，早期脚本定位错误/JSON 转义断言失败与修正后结果分别保留。

官方图像输入能力参考[OpenAI Docs](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat)。本页限制是 PIM 当前切片选择，不是所有供应商的统一上限；实际支持与质量以对应模型验证为准。
